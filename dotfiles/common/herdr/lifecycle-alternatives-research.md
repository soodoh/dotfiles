# Herdr / Pi lifecycle alternatives — research only

Registry/source checked 2026-09-06 UTC. Target: Herdr 0.8.2, native Pi 0.85.1. No installation, execution of downloaded code, configuration changes, or repository writes.

## Conclusion

**Keep the official vendored reporter as the sole lifecycle authority; add a small sibling adapter for native Pi `ui_prompt_start` / `ui_prompt_end` → counted `herdr:blocked`, if implementation is subsequently approved.** The parent’s installed-host inspection establishes these native prompt events exist in Pi 0.85.1. None of the inspected alternatives consumes them. Pi does not lack prompt lifecycle signals: the official reporter simply does not currently translate these host signals.

An actual npm replacement exists: **`@signalridge/pi-herdr-state@1.2.3`**, but it still requires exactly the same `herdr:blocked` producer and its declared Pi peer range excludes 0.85.1. **`@andrewjacop/pi-herdr@0.4.0`** also self-reports and catches the installed question package’s legacy signal, but bundles broad orchestration and has weaker blocked-state semantics. Neither is the best fix for this checkout.

## Why the native adapter fits the exact local gap

* Published **`@juicesharp/rpiv-ask-user-question@2.9.0`** confirms `ASK_USER_BLOCKED_EVENT = "rpiv:ask-user:blocked"` with `{active:boolean}`. The question UI brackets `ctx.ui.custom` with true and a finally-protected false (also its RPC path). It does not emit `herdr:blocked`. The parent independently verified this exact installed version. [7]
* Published **`pi-subagents@0.66.0`** already emits `herdr:blocked` for root-session async attention, balanced as attention changes or clears/disposes (`src/integrations/herdr-status.ts`, `syncBlocked`). Preserve this producer; it covers attention beyond a currently open local modal. [8]
* Parent inspection of native Pi 0.85.1 identifies coalesced `ui_prompt_start/end` around `select`, `confirm`, `input`, `editor`, and `custom`; notifications are best-effort and not awaited. Cite the pinned host docs/source below for independent review. These hooks make a RPIV-only adapter unnecessarily narrow. Do **not** additionally translate the legacy RPIV signal for the same UI path. [9]
* The proposed sibling should only produce bus signals, never call Herdr directly or replace `herdr:pi`. Gate to native TUI, valid Herdr environment, and the same root/non-child policy as the official reporter. Hold/release only its own blocked contribution; do not zero the shared reporter counter or clear subagent attention. Since host prompts are coalesced, one adapter-held token is sufficient for that host aggregate; the reporter continues counting independent producers.
* Future acceptance tests should cover prompt open/answer, cancellation/error, overlapping/nested prompts, concurrent subagent attention (closing the UI must leave the pane blocked), RPC/headless/child suppression, shutdown/reload cleanup and listener disposal. Any cleanup must only release an acquired contribution, and should not emit guessed idle/working state. Best-effort delivery and reload ordering require host-level validation.
* Scope limit: do not promise builtin menus/trust dialogs, external processes/UIs, or arbitrary implementations that bypass Pi’s instrumented `ctx.ui` wrappers. A normal assistant question after the run settles is **idle/done**, not an in-flight modal block. Screen heuristics cannot compensate for absent producer signals while official authoritative lifecycle reporting suppresses screen fallback.
* Parent validation: `/tmp/herdr-ui-prompt-audit.mjs` instantiated the **actual installed ExtensionRunner** in clean temporary HOME with fake dialog promises and an emit observer. All five wrapped methods emitted paired start/end on resolve/reject; two overlapping waits yielded one outer start and an end only after both finished. **PASS**, limited to native wrapper emission—not GUI/Herdr delivery, model calls, or native extension event dispatch. Parent found matching installed runner SHA-256 for repository and mise launcher copies: `0de12ed1275e02595f92476eec3f61ae1f2e54fd2225ced721ddc90af58a5e61`. Relevant implementation: `setUIContext` / `wrapUIPromptContext` / `withUIPrompt`, installed compiled runner lines 269–313.
